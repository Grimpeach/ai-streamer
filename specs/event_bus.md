# Спецификация: Шина событий (Event Bus)

Реализация: `src/core/event_bus.py`, модели — `src/core/events.py`.
Дополняет раздел «Шина событий и Приоритеты» из [architecture.md](architecture.md).

## 1. Приоритеты

| Приоритет | Значение | Источник | Прерывает генерацию |
|---|---|---|---|
| `INTERRUPT` | 1 | Push-to-Talk хоста, `system.preempt`, `system.shutdown` | да |
| `HIGH` | 2 | Twitch: донаты, подписки, рейды | нет |
| `NORMAL` | 3 | Twitch: чат, служебные события LLM/TTS | нет |
| `LOW` | 4 | Фоновая активность (idle-реплики, телеметрия) | нет |

Приоритет и флаг `preemptive` подставляются по типу события (`DEFAULT_PRIORITY`,
`PREEMPTIVE_TYPES`), но могут быть заданы явно при публикации.

## 2. Гарантии доставки

1. **Порядок.** Очередь — куча по `(priority, seq)`. Событие приоритета 1
   обгоняет любой накопленный чат независимо от размера очереди.
2. **Неблокирующая публикация.** `publish()` не ждёт обработчиков; обработчики
   запускаются диспетчером как отдельные задачи.
3. **Параллельность.** Обработчики одного события выполняются одновременно.
   Если порядок важен (речь), подписка объявляется `exclusive=True` либо
   компонент ведёт собственную очередь (так сделано в TTS).
4. **Свежесть.** Событие с истёкшим `ttl_s` отбрасывается диспетчером и не
   доходит до обработчика: отвечать на сообщение чата минутной давности хуже,
   чем не отвечать.
5. **Защита от переполнения.** При достижении `max_queue_size` вытесняется
   наименее ценное событие: сначала по низшему приоритету, затем самое старое.

## 3. Прерывание (Preemption)

Требование `.cursorrules` п.4: PTT имеет абсолютный приоритет и мгновенно
отменяет текущую генерацию LLM/TTS.

Механика при публикации preemptive-события:

1. Инкрементируется `generation` шины.
2. Взводятся все выданные `PreemptionToken` — долгие генерации видят
   `token.cancelled` и получают `Preempted` при следующей проверке.
3. Отменяются все активные обработчики подписок с `preemptible=True`.
4. Из очереди вычищаются события приоритетов `NORMAL` и `LOW`, а также
   отложенные события прерываемых подписок.

Ключевое свойство: шаги 1–4 выполняются **синхронно внутри `publish()`**, до
постановки события в очередь. Прерывание не ждёт, пока диспетчер разгребёт
очередь, поэтому задержка не зависит от нагрузки чата.

Подписки, которые прерывать нельзя (`preemptible=False`): логирование,
метрики, сброс буферов TTS. Если сбросить буфер по PTT не удастся, остаток
фразы «догонит» хоста и заговорит поверх него.

### Кооперативная отмена

Жёсткая отмена задачи не годится там, где нужно освободить ресурс (закрыть
HTTP-стрим к vLLM, остановить аудио-поток). Такой код берёт токен:

```python
with bus.preemption_scope("llm") as token:
    async for chunk in llm.stream(prompt, token):
        token.raise_if_cancelled()
        ...
```

## 4. Потоки

Хук клавиатуры PTT и аудио-колбэк PortAudio живут вне event loop, поэтому
публикуют события через `publish_threadsafe()` (внутри — `call_soon_threadsafe`).

## 5. Конвейер Фазы 1

```
twitch.chat (P3) ─┐
twitch.donation (P2) ─┼─> brain.route ──> llm.request ──> LLM (stream)
ptt.host_speech (P1) ─┘                                    │
                                                           ├─> llm.chunk   (оверлей/сабы)
                                                           └─> tts.request (по фразам)
                                                                    │
                                                                    └─> tts.chunk ──> аудио
```

Нарезка ответа на фразы выполняется в LLM-модуле: только там поток токенов
упорядочен. Сборка фраз из отдельных событий `llm.chunk` была бы гонкой,
поскольку обработчики событий выполняются параллельно.

## 6. Метрики

`bus.stats` считает: `published`, `delivered`, `completed`, `failed`,
`preemptions`, `cancelled_handlers`, `dropped_preempt`, `dropped_stale`,
`dropped_overflow`. Рост `dropped_*` — сигнал, что конвейер не успевает за чатом.
